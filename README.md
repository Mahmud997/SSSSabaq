# USTAZ AI PRO MAX

Платформа для подготовки учебно-методических материалов с помощью AI. Проект объединяет генератор КСП/КМЖ, редактор документов, конструктор заданий, презентации, планирование, библиотеку материалов и административную панель.

> **Статус:** Stage 10. Репозиторий подготовлен к публикации на GitHub. Перед открытым production-развёртыванием ознакомьтесь с разделом «Известные ограничения и безопасность».

## Возможности

### Для учителя
- Создание рабочего пространства без регистрации: профиль учителя, школа, населённый пункт и предметы.
- Генерация КСП/КМЖ с учётом предмета, класса, темы, языка, длительности и условий кабинета.
- Редактор документов с пятью обязательными модулями, дополнительными разделами и таблицами.
- Редактирование ячеек и блоков, добавление/удаление/перемещение строк и столбцов.
- Перегенерация отдельных блоков через AI и создание нескольких вариантов заданий.
- Конструктор материалов: задания A/B/C, карточки, рабочие листы, тесты, рубрики и дескрипторы.
- Создание и редактирование презентаций на 6–14 слайдов.
- Планирование: КТП, СОР, СОЧ, диагностика, годовые и тематические планы.
- История версий, восстановление, избранное и пользовательские шаблоны.
- Экспорт DOCX, PPTX и XLSX; печать в PDF средствами браузера.
- JSON-резервная копия и импорт материалов в рабочее пространство.

### Общая библиотека и администрирование
- Отправка обезличенной копии материала на публикацию.
- Публикации становятся общедоступными только после одобрения администратора.
- Админ-панель: рабочие пространства, материалы, модерация, аудит, статистика и журнал AI.
- Настройка AI-провайдера, модели и промптов через админ-панель. Сами API-ключи задаются только на сервере.

### Поддерживаемые AI-провайдеры
- Google Gemini
- OpenAI
- Anthropic
- xAI

## Стек

- **Frontend:** HTML, CSS, vanilla JavaScript
- **Backend:** Python 3.12, FastAPI, Pydantic
- **Database:** PostgreSQL 16, SQLAlchemy 2
- **AI:** HTTP API выбранного провайдера
- **Документы:** python-docx, python-pptx, openpyxl
- **Deploy:** Docker Compose, Nginx, HTTPS

## Быстрый запуск через Docker

Требуется Docker Engine и Docker Compose plugin.

1. Склонируйте репозиторий:

   ```bash
   git clone https://github.com/USERNAME/ustaz-ai-pro-max.git
   cd ustaz-ai-pro-max
   ```

2. Создайте конфигурацию:

   ```bash
   cp .env.example .env
   ```

3. В `.env` задайте уникальные значения:
   - `POSTGRES_PASSWORD`
   - `DATABASE_URL` — пароль в URL должен быть URL-кодирован, если содержит специальные символы
   - `APP_SECRET`
   - `ADMIN_SECRET`
   - API-ключ выбранного AI-провайдера

   Не используйте значения `CHANGE_...` в рабочей среде.

4. Запустите приложение:

   ```bash
   docker compose up -d --build
   ```

5. Проверьте API:

   ```bash
   curl http://localhost:8080/api/health
   ```

   Откройте `http://localhost:8080`.

Для публичного сервера используйте production-конфигурацию с Nginx и HTTPS. Подробная инструкция — в [DEPLOY.md](DEPLOY.md).

## Локальный запуск без Docker

Из корня репозитория:

```bash
python -m venv .venv
# Linux/macOS:
source .venv/bin/activate
# Windows PowerShell:
# .venv\Scripts\Activate.ps1

pip install -r backend/requirements.txt
```

Установите переменные окружения для PostgreSQL и секретов, затем:

```bash
cd backend
uvicorn app.main:app --host 127.0.0.1 --port 8000 --reload
```

Откройте `http://127.0.0.1:8000`. Для локальной разработки допустима SQLite, если задать `DATABASE_URL=sqlite:///./ustaz_dev.db`.

## Конфигурация

Основные переменные `.env`:

| Переменная | Назначение |
|---|---|
| `DATABASE_URL` | Строка подключения SQLAlchemy |
| `POSTGRES_DB` | Имя базы PostgreSQL |
| `POSTGRES_USER` | Пользователь PostgreSQL |
| `POSTGRES_PASSWORD` | Пароль PostgreSQL |
| `APP_SECRET` | Серверный секрет для HMAC-хеширования ключей пространств |
| `ADMIN_SECRET` | Секрет доступа к админ-панели |
| `AI_PROVIDER` | `gemini`, `openai`, `anthropic` или `xai` |
| `AI_MODEL` | Необязательное переопределение модели |
| `AI_TIMEOUT_SECONDS` | Таймаут AI-запроса |
| `GEMINI_API_KEY` | Ключ Gemini |
| `OPENAI_API_KEY` | Ключ OpenAI |
| `ANTHROPIC_API_KEY` | Ключ Anthropic |
| `XAI_API_KEY` | Ключ xAI |

Ключи AI не должны попадать во frontend, GitHub Issues, логи или публичные коммиты.

## API

После запуска интерактивная документация доступна по адресу `/docs`, OpenAPI — `/openapi.json`.

Основные группы:
- `/api/workspaces` — создание и профиль рабочего пространства.
- `/api/lessons` — материалы, редактор, версии и экспорт.
- `/api/materials` — генерация учебных материалов.
- `/api/presentations` — презентации и экспорт.
- `/api/planning` — планирование и оценивание.
- `/api/library` — общая библиотека.
- `/api/admin` — закрытая административная панель.
- `/api/workspace/backup` и `/api/workspace/restore` — резервное копирование.

Для личных API-запросов передавайте `X-Workspace-Key`. Для административных запросов используется `Authorization: Bearer <ADMIN_SECRET>`.

Локально можно выполнить:

```bash
python -m compileall -q backend/app
for file in frontend/*.js; do node --check "$file"; done
pip install -r requirements-dev.txt
cd backend
pytest -q ../tests
```

GitHub Actions выполняет те же проверки при push и pull request.

Проверки не требуют реальных AI-ключей и не вызывают внешние AI API.

## Известные ограничения и безопасность

Перед использованием в открытом production обязательно учтите:

1. **Миграции БД:** сейчас таблицы создаются через `Base.metadata.create_all()`. Версионированных миграций Alembic пока нет. Изменения моделей требуют отдельного плана миграции.
2. **Ограничение запросов:** встроенного rate limiting нет. Публичное создание рабочих пространств может быть целью спама; добавьте лимиты на reverse proxy/WAF или реализуйте rate limiting.
3. **Администратор:** предусмотрен общий секрет, но MFA, индивидуальные учётные записи и ротация секретов не реализованы.
4. **Ключ рабочего пространства:** IndexedDB — это локальное хранилище браузера, а не шифрование. При XSS или доступе к устройству ключ может быть раскрыт. Используйте HTTPS и защищайте устройство.
5. **Язык интерфейса:** селектор языка присутствует в интерфейсе, но переключение всего UI на казахский, английский и узбекский пока не реализовано. Язык генерируемого документа задаётся отдельно.
6. **Обезличивание:** автоматическая фильтрация не гарантирует полное удаление персональных данных из текста, изображений, метаданных и вложений. Проверяйте копию вручную перед публикацией.
7. **AI-статистика:** журналирование фиксирует вызовы и задержки, но учёт токенов и детализация по рабочему пространству пока не полные.
8. **Резервные копии:** настройте автоматический backup PostgreSQL и периодически проверяйте восстановление. JSON-бэкап рабочего пространства не заменяет резервную копию всей базы.
9. **Эксплуатация:** перед обновлением production создавайте backup и проверяйте изменения на тестовой копии.

Подробности — в [SECURITY.md](SECURITY.md) и [DEPLOY.md](DEPLOY.md).
